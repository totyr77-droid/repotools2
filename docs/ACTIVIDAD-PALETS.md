# Actividad de palets — desarrollo

Auditoría: api/stock.php centraliza claim/import/save_product/delete_product/description/delete/invite/accept/decline/revoke/leave, con permisos stock_editable, mutex/transacción y stock_operations por usuario+operation_key. Palets no se renombran: el número es inmutable; se registra cambio de descripción y referencia de producto. Generar etiqueta no crea palet y no suma actividad. Consultas, notificaciones, refresh y expiración técnica no se registran. Una invitación pendiente tampoco concede acceso: colaborador agregado se registra cuando acepta.

Migración27: pallet_activity guarda actor user_id, palet, producto nullable, acción, metadata mínima y timestamp; FK ON DELETE SET NULL conserva eventos de productos eliminados. Palets se liberan lógicamente, IDs nuevos al reutilizar código mantienen historiales separados. Índice(pallet_id,id) cubre lista por palet y cursor estable descendente; sin duplicar los índices de otras tablas. No se almacena email, cookies, payload completo ni nombre privado. Nombre público se resuelve al leer por ID actual, fallback Usuario. Historial viejo no se inventa ni se importa de los eventos administrativos que guardaban payloads amplios.

Registro por diferencias reales antes/después dentro de transacción y después de permisos/operación confirmada. Creación, eliminación, descripción, producto agregado/quitado/unificado, cantidad, referencia, vencimiento agregado/modificado/quitado y colaborador aceptado/removido. Al unificar lotes se conservan cambio de cantidad y de vencimiento, más el evento de unificación. Sin cambios reales no hay evento. Caché stock_operations responde antes de capturar/registrar, por lo que retries offline producen una sola mutación/historial. Un error revierte ambos. stock_save_product ahora retorna ID real, necesario para identificar palet nuevo/reubicado y su revisión; no cambia reglas de cantidades ni permisos.

API GET api/pallet-activity.php?pallet_id=…&cursor=… comprueba propietario, colaborador actualmente accepted o administrador/manager con permiso existente. Pendiente/revocado/ajeno403, anónimo401, método noGET405. Palet eliminado sigue consultable por autorizado mediante helper/API; no se agregan pantallas de archivo. No existe borrado individual de eventos. Primera página25, máximo helper30; cursor permite Cargar más. Consulta actor LEFT JOIN y colaboradores consultados por lote: sin N+1. Helper reutilizable admite límite3–5 sin implementar dashboard.

Detalle del palet: Actividad plegable bajo productos, iconos locales por acción, nombres y textos cortos, fechas argentinas y sin segundos. Sin modal adicional ni botón principal. Fetch únicamente al desplegar, loader local/botón, reset al cambiar palet y actualización si se vuelve a renderizar abierto; cancelación al cerrar/navegar. En offline informa Disponible al conectar, no reconstruye cola ni guarda historial nuevo en cliente.
